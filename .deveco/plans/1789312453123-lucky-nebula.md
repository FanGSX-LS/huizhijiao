## Goal

修复 AmapView 黑屏问题，让签到页（pick 模式）和日历详情弹窗（show 模式）正常显示高德地图。

## Scope / Non-goals

**In scope:**
- `amap_map.html` 加载策略改造 + 诊断日志
- `AmapView.kt` WebView 加载方式改造 + console 桥接
- 按 Logcat 输出执行对应的修复阶梯
- 验证两处地图 + release 构建

**Out of scope:**
- 更换地图供应商或改用高德原生 SDK
- 高德控制台 Key 配置（如需用户操作，给出指引）

## Current State And Constraints

**证据与已排除项：**
- R8 混淆已排除：`proguard-rules.pro:35` 有 `-keep class com.gxjzy.huizhijiao.** { *; }`
- 硬件加速已排除：Manifest 未禁用（API 31+ 默认开启）
- Key 本身有效：参考项目 `C:\Users\FanGSX\Desktop\tetst\webapp` 用同一 key（`42e40e2f23dff717d37621e46933147b`）在浏览器正常，无需 securityJsCode
- 用户确认 Key 无域名白名单（或不清楚）

**三个版本均黑屏的变量组合：**

| 尝试 | 页面来源 | SDK 加载 | 结果 |
|---|---|---|---|
| #1 | `file:///android_asset/` | `callback=initMap` 异步 | 黑屏 |
| #2 | `loadDataWithBaseURL` | `callback=initMap` 异步 | 黑屏 |
| #3 当前 | `file:///android_asset/` | 同步+`onPageFinished` 调 initMap | 黑屏 |

**当前缺失的关键诊断**：`typeof AMap` 检测、script `onerror`、`window.onerror`、WebGL 检测、console→Logcat。目前 try/catch 吞掉错误，黑屏原因不可见（loading 层 `#1a1a2e` 深色背景外观也是"黑屏"）。

**剩余根因假设（排序）：**
1. **外部脚本从 `file://` 源被阻止**（MIUI WebView 策略）→ `AMap is not defined`
2. **Key referer/域名校验拒绝**（data: 源或空 referer）
3. **WebView WebGL 不可用** → `AMap.Map` 创建成功但瓦片渲染黑

**参考项目关键模式**（`frontend/index.html`，浏览器可用）：
- `<link rel="stylesheet">` + `<script src="https://webapi.amap.com/maps?v=2.0&key=...">` 同步加载，无 callback 参数
- 加载后直接 `new AMap.Map(...)`，无 onPageFinished 间接调用

## Design

### 策略：一次构建同时做「最可能修复」+「全量诊断」

改用 `loadDataWithBaseURL("https://webapi.amap.com/", ...)` 让页面源为 https（消除 file:// 子资源阻止，且 referer 为高德自家域名），配合参考项目的同步加载模式；同时埋满诊断日志，若仍黑屏，Logcat 一次性定位。

### 1. `amap_map.html` 改造

- 占位符 `{{PICK_MODE}}` → Kotlin 读取 asset 时替换为 `true`/`false`，`var pickMode = {{PICK_MODE}};`
- 保持 `<link>` + 同步 `<script src>`（去 callback）
- **内联脚本直接执行 `initMap()`**（模仿参考项目，消除 onPageFinished 竞态；`onPageFinished` 里做兜底 `if (!map) initMap()` 防重入）
- 诊断埋点：
  - `<script onerror>` → `console.error('amap script load failed')`
  - 脚本后立刻 `console.log('typeof AMap = ' + typeof AMap)`
  - `console.log('webgl = ' + !!document.createElement('canvas').getContext('webgl'))`
  - `window.onerror` → console + bridge
  - `initMap` try/catch 里 `console.error('initMap: ' + e.message)`（不再吞）
  - `map.on('complete')` → `console.log('map complete')` + bridge `onMapReady()`

### 2. `AmapView.kt` 改造

- **加载方式**：读 asset HTML 字符串 → 替换 `{{PICK_MODE}}` → `loadDataWithBaseURL("https://webapi.amap.com/", html, "text/html", "UTF-8", null)`
- **console 桥接**：`WebChromeClient.onConsoleMessage` → `Log.d("AmapView", "console: ...")`（JS 的 console.error 全部进 Logcat）
- 保留 `Android.onMapReady`/`onLog`/`onLocationPicked` bridge 与 `mapReady` 门控的 setMarker 逻辑
- `onPageFinished` 兜底：`if (typeof map === 'undefined' || !map) initMap()`（用 evaluateJavascript 检查）

### 3. 修复阶梯（按 Logcat 输出执行）

| Logcat 现象 | 根因 | 动作 |
|---|---|---|
| `typeof AMap = undefined` 或 script load failed | 脚本仍被阻止 | 改本地起 NanoHTTPD(127.0.0.1) 提供 HTML，origin 为 http |
| console 出现 key 错误（INVALID_USER_KEY / PLAT_NOMACH / REFERENCE 限制） | Key 域名/referer 校验 | 指引用户去 console.amap.com 检查 Key 类型为「Web端(JS API)」并清空白名单，或换白名单为 `*` |
| `typeof AMap = function` 但 `webgl = false` | WebView 无 WebGL | 回退方案：show 模式用高德静态图 REST API（`restapi.amap.com/v3/staticmap`）；pick 模式保持 Web 先行并提示（计划内标注为后续单独任务，不阻塞本次） |
| `map complete` 日志出现但仍黑屏 | 瓦片/渲染层 | 换 `mapStyle` 为默认（去掉 dark）测试；检查瓦片网络请求 console |

## Risks And Compatibility

- **loadDataWithBaseURL 源为 `https://webapi.amap.com/`**：该域下 JS 文件、相对资源加载正常；若 Key 有 referer 限制，此源最容易通过校验（高德自家域名）
- **若三方向全堵**（脚本+key+webgl 全败）：回退 NanoHTTPD 本地服务器（origin `http://127.0.0.1`），约 +2 个依赖文件，作为修复阶梯第 1 档的备选
- **诊断日志含 console 全量输出**：仅打 Logcat debug 级，release 无用户可见影响
- **静态图回退**（仅 show 模式）需要 key 可访问 restapi，属后续任务
